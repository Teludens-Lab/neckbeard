# End-user onboarding

Design around goals expressed in product language. Trace access, first success, repeated work, collaboration, and recovery where supported. Explain visibility, status, finality, and correction at decision points. Do not teach implementation internals unless they help the user act. Deliver a first-task tutorial and task-oriented help; add screenshots only from a real build. Verify role access and exact interface labels. For a library or CLI, treat its consumers as end users.
