# Audio, video, and scripts

Read `references/production-standards.md` and use `references/production-brief-template.yaml` to resolve the production contract. Use `references/storyboard-template.csv` for shot planning. Select script, audio, video, or a combined package from the user's goal. Do not require media production for ordinary written onboarding.

1. Establish audience, learning objective, supported workflow, revision, delivery channel, duration, branding, accessibility needs, and requested formats. Use supplied direction and defaults for routine choices; ask only for blocking decisions.
2. Inspect implementation and verify the chosen role and workflow. Use an accessible running application and demonstration data for authentic screen capture. Record evidence and starting/reset state. Do not fabricate interface recordings.
3. Discover actual tool capabilities: app interaction, screen recording, voice generation, editing/rendering, captions, and media inspection. Interaction or screenshots alone do not establish recording capability. Report missing capabilities and deliver the supported subset. Never describe scripts, stills, or storyboards as completed videos. Do not silently substitute generated UI for actual product footage.
4. Prepare a coherent written tutorial, script, pronunciation dictionary, storyboard, and production brief as requested. Adapt standalone audio for listeners who cannot see the screen. Keep exact product labels and outcomes consistent across formats.
5. Where tools support it, capture footage and synthesize narration, then assemble with purposeful motion, holds, reviewed captions, and restrained annotations. Follow applicable tool and file-format instructions. Use stock/generated explanatory imagery only when appropriate and visibly distinguish it from actual interface evidence.
6. Inspect rendered video and listen to actual audio with supported playback/inspection tools. Check action truthfulness, narration sync, pronunciation, legibility, caption accuracy/timing, important visual descriptions, and export properties. Record checks that tools cannot perform as unverified. Never claim listening or full playback from metadata alone.
7. Deliver only artifacts actually produced, with sources and a compact verification record. Preserve shot/feature dependencies for future updates. A production-ready script package is a valid partial deliverable when rendering is unavailable, but explicitly state the finished-media limitation.

No bundled recorder, voice engine, or editor is supplied by this component. Installing it adds orchestration instructions, standards, and templates; it does not install external services or guarantee export capabilities.

Before processing any screenshot, narration, demo data, caption or render asset, apply the data-handling gate in references/governance.md. Validate the configured project profile, inventory all media_assets, then run scripts/governance.py gate for the exact approved tool, operation, execution mode and input IDs. Block on missing policy, unknown classifications, incomplete review or denial. Support offline mode and never infer that a tool is approved from its availability. Preserve the receipt; do not send an input before its gate passes.

Deliver finished video as MP4 and standalone audio as MP3. Keep WAV only as an optional master. Read references/delivery-formats.md; scripts, storyboards, captions and transcripts support but do not replace finished media. A complete tutorial also includes MD, HTML and PDF editions derived from the same verified content.
